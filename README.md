# おでかけナビ なかつ

スマホの操作に慣れていない中津市の高齢者を想定した、バス乗り換え案内アプリの体験版です。企画書の「自宅を登録する → 目的地・到着時刻を選ぶ → お迎えの申込内容を確認する → 乗り換え案内を見る」という流れを試せます。

**実際の運行情報・予約システムとは連携していません。** 施設名は中津市内の施設を参考にしていますが、時刻・運賃・経路・バス停はサンプルです。地図は説明用の模式図で、実際のおでかけには使用できません。予定を保存しても交通事業者へ予約は送信されません。

## 開発を始める

Node.js 24・npm 11 で動作確認しています。API キーや外部データベースは不要です。既存の `/workspace/-navi-` チェックアウトを利用します。

```bash
cd /workspace/-navi-
npm ci --cache /tmp/navi-npm-cache
npm run dev
```

開発サーバーは `0.0.0.0` のポート `5173` で起動します。ポート使用中の場合は自動で別ポートへ切り替わらず終了するため、既存のサーバーを確認してください。クラウド環境では上記のキャッシュ指定を使うと、ホームディレクトリへの書き込み権限に依存せず導入できます。

## 確認コマンド

```bash
npm run build
npm test
npm run test:e2e
```

- `build`：TypeScript の型検査と本番用ビルド。生成先は `dist/`。
- `test`：経路計算・入力検証・ブラウザ保存処理の単体テスト。
- `test:e2e`：Chromium でデスクトップとスマートフォンの操作を確認。自宅登録、経路検索、申込体験、再読み込み後の復元、案内、削除などを検証。

E2E は `/usr/bin/chromium` のブラウザを使用します。実行ファイルの環境変数による上書きには対応していません。他の環境では Chromium を用意し、必要に応じて `playwright.config.ts` の `launchOptions.executablePath` を変更してください。開発サーバーがない場合はテストが起動し、ローカル開発時はポート `5173` の既存サーバーを再利用します。CI ではテスト用にポートを空けてください。失敗時の画面・トレースは `test-results/` に出力します。

## 試せる機能

- ニックネームと自宅の地域・地図上の位置を登録。地図はマウス・タッチ・キーボードに対応。
- 目的地・日付・到着希望時刻から、デマンドバスと路線バスを組み合わせたサンプル経路を検索。バス停まで歩く候補も表示。
- お迎え内容を確認し、実際の予約が送信されないことに同意して体験用の予定を保存。
- 保存した予定から徒歩・お迎え・路線バスの案内を順番に確認。対応ブラウザでは音声読み上げも利用可能。
- 文字サイズ切り替え、スマートフォン用メニュー、使い方と登録情報の削除。

## 保存する情報

アカウント作成やバックエンドはありません。ニックネーム、自宅の座標・呼び名、予定は同じブラウザの `localStorage` に保存します。

| キー                 | 内容                                   |
| -------------------- | -------------------------------------- |
| `nakatsu-profile-v1` | ニックネーム・自宅                     |
| `nakatsu-trips-v1`   | 予定・選択した経路・その時点の登録情報 |

別の端末やブラウザとは共有されません。ブラウザの保存データを消すと復元できません。「使い方」→「登録情報を削除する」から、このアプリの登録情報と予定を削除できます。個別の予定は「おでかけ予定」から削除できます。

画面を読み込んだ後の検索・保存は外部 API なしで動作しますが、オフラインでの再読み込みには対応していません。

## 実運用へ進めるために

現在の実装は操作検証用です。実運用には、次の仕様・連携を交通事業者などと確認し、実装・検証する必要があります。

1. 公式時刻表・GTFS などの利用許諾と更新方法、運行日・運休・乗り継ぎを考慮した経路検索。
2. デマンド交通の対象地域・利用資格・事前登録・予約期限・定員・料金などの運行条件。
3. 事業者の予約 API または実際の受付手段との連携と、受付・確定・取消の状態管理。端末内の予定保存と予約確定の区別。
4. 実地図・住所検索・位置情報・徒歩経路の提供元と精度、利用者への説明。
5. 認証、適切なアクセス制御、個人情報の保存・削除方針を備えた安全なバックエンドと、事業者との連携確認。

実データへの置き換え後は、高齢の利用者による操作確認と実際の運行条件での検証も必要です。
